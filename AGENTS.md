# chironjp contributor instructions

Keep this repository a sanitized, runnable public preview. Use generic VPS paths, ports, domains, and blank runtime defaults. Never add credentials, private candidate facts, application records, operational logs, machine-specific addresses, retained browser data, screenshots containing personal information, or code from private sourcing systems.

Preserve the core boundary: agents may discover roles, select canonical resume content, and prepare the actual employer form for Review. Submit, Send, Confirm, and equivalent final actions are performed only by the human owner in the rendered employer interface. Tests and fixtures must never be described as real delivery or submission evidence.

Adapt upstream work only when its license, immutable source revision, changed-file provenance, and required notices are present in `THIRD_PARTY_NOTICES.md`. Do not imply upstream endorsement.

Run focused tests for changed surfaces and `npm run audit:release` before publishing code. Keep fictional examples under `examples/fictional`; templates and runtime defaults stay free of personal answers.

Prefer the smallest coherent change. A failed strategy is useful evidence, but retain a recovery strategy only after a changed approach produces a verified postcondition.
